# Fiber

React Fiber is a scheduler-enabled reconciliation engine that allows React to:

prioritize updates using lanes/priorities
interrupt/cancel obsolete renders
pause and later continue rendering work
split rendering into small chunks
yield control back to the browser to keep UI responsive

And importantly:

only the render/reconciliation phase is interruptible
the commit phase (DOM mutations) is still synchronous and atomic

This is what enables concurrent features like transitions, Suspense, and responsive rendering under load.

# useDeferredValue

Marks a CONSUMED VALUE as non-urgent:

```text
const deferred = useDeferredValue(value);
```

Keep showing old UI until React has time to render the new one. So it is scheduler priority mechanism.

useDeferredValue marks consumption of a value as non-urgent
It returns old value temporarily and schedules low-priority update
Rendering work is NOT reduced automatically (sometimes even more work occurs)
Main optimization is responsiveness: urgent updates can commit first
Deferred DOM commits are delayed until low-priority render finishes
Deferred value eventually converges to source value

# Effect Hooks Timing

* useEffect - runs after browser paint
* useLayoutEffect - runs after DOM commit but before paint (Blocks paint)
* useInsertionEffect - runs before DOM layout

# useEffectEvent

Marks function dependencies as non-reactive for an effect. Can be used inside useEffect only. Does not have stable
reference identity (changes on every render).

Useful for cases when non-reactive (or sometimes reactive) value must be accessed inside an effect, but effect itself
must not depend on it.

# useOptimistic

Used with Actions (startTransition) to show optimistic value while side-effect is pending (transition is in progress).
When effect is done -> optimistic value converges to its source.

```text
Optimistic state only renders while an Action is in progress, otherwise value is rendered.
```

reducer is an important part of optimistic hook, it defines how React should update optimistic value when state is
changed during Transition pending.

# useTransition

Marks a PRODUCED VALUE as non-urgent

Does not let components to suspense again during a Transition:

If Suspense was displaying content for the tree, but then it suspended again, the fallback will be shown again unless
the update causing it was caused by startTransition or useDeferredValue.

# Strict Mode

Your components will re-render an extra time to find bugs caused by impure rendering.
Your components will re-run Effects an extra time to find bugs caused by missing Effect cleanup.
Your components will re-run refs callbacks an extra time to find bugs caused by missing ref cleanup.
Your components will be checked for usage of deprecated APIs.

# prerenderToNodeStream

The static prerenderToNodeStream API is used for static server-side generation (SSG). Unlike renderToString,
prerenderToNodeStream waits for all data to load before resolving.

# RSC

Server Components do not hydrate. Their JS is not shipped to the browser. React docs describe them as components that
render ahead of time in a separate server environment from the client app.

```text
[
    "h1", "Hello Roman",
    client_reference("Counter", { initialValue: 0 })
]
```

That serialized format is commonly called the Flight payload. The original RFC describes RSC as letting apps span server
and client, combining server rendering with client interactivity.

# React Server Functions

Special functions marked with 'use server' can be passed from RSC to CSC. Bundler will generate special refs (via
Symbols) and use it in browser runtime (or node.js runtime) like simple endpoint (POST)

A Client Component may render:

1. once on server (SSR)
2. again on client (hydration)
3. many more times on client

while a Server Component:

renders only on server
never hydrates
never rerenders in browser
