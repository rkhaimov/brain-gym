## RDM/MDM система управления справочными и мастер-данными

Enterprise web-приложение для управления справочными данными (RDM) и мастер-данными (MDM), поставляемое заказчикам как
коробочное решение (RDM или RDM+MDM). Система предназначена для внутренних пользователей и включает сложные формы,
процесс согласования и публикации данных, высоконагруженные табличные представления, batch-операции и развитую модель
прав доступа через capabilities.

Проектная роль: Lead Frontend Developer

  приложений.

## Ассистент медсестры палаты интенсивной терапии

Описание проекта:
Высоконагруженная система мониторинга и сопровождения терапии пациентов палаты интенсивной терапии. Приложение
обеспечивает отображение жизненных показателей пациента в реальном времени, управление интерактивным планом терапии и
контроль выполнения медицинских процедур. Система поддерживает режимы alarm/stale-data, работу с real-time потоками
данных от медицинских приборов, многоакторную работу с пациентом и длинные интерактивные таймлайны процедур с высокой
плотностью данных.

Состав команды: 40 человек
Проектная роль: Lead Frontend Developer

### Выполненные задачи:

* Спроектировал и реализовал frontend-архитектуру safety-critical системы мониторинга пациентов с акцентом на
  корректности, надёжность и производительность.
* Разработал реактивную модель отображения жизненных показателей пациента с real-time обновлением данных через
  SSE.
* Реализовал state-machine модель терапий и процедур, предотвращающую выполнение действий по устаревшим назначениям
  врача, а также исключающую конфликтные изменения.
* Спроектировал механизм stale-data detection и автоматического перехода интерфейса в read-only режим при потере

* Реализовал виртуализированную карточку пациента с ленивой загрузкой секций, стратегиями prefetch и pyramid/LOD

* Спроектировал строгую типизированную модель состояния медицинских данных с runtime валидацией контрактов.
* Спроектировал эффективные Playwright визуальные regression-тесты для UI.
* Участвовал в проектировании UX для сценариев работы медсестёр и врачей в условиях real-time мониторинга, высокой

## OBD Companion Platform

Описание проекта:
Кроссплатформенное мобильное приложение для Android/iOS, выполняющее real-time-считывание телеметрии автомобиля через
BLE OBD-II адаптеры (ELM-compatible), анализ параметров автомобиля и фоновую синхронизацию данных с внешней системой.
Приложение поддерживает offline-first сценарии, устойчивую работу при нестабильном соединении и отображение
диагностической информации (DTC, состояние подключения, телеметрия автомобиля) в реактивном интерфейсе.

Состав команды: 20 человек
Проектная роль: Lead Frontend Developer

### Выполненные задачи:

* Спроектировал и реализовал архитектуру с упором на кроссплатформу и поддержку полиморфных runtime.
* Реализовал real-time конвейер обработки OBD-телеметрии с вынесением CPU-intensive задач в Flutter isolates, что
  позволило исключить блокировки UI-потока и обеспечить стабильную работу интерфейса во время активной передачи данных.
* Разработал offline-first механизм синхронизации:
  * локальная очередь на SQLite,
  * batching,
  * delta encoding,
  * управление backpressure,
  * политики retry/reconnect,
  * сценарии частичной деградации при отсутствии BLE/интернета.
* Спроектировал metadata-driven систему динамических PID-параметров с поддержкой:
  * кастомных PID,
  * формул парсинга,
  * runtime-конфигурации динамичных параметров,
  * адаптивных sampling политик.
* Реализовал отдельную библиотеку модели PID на Dart с компиляцией в JS для использования в web runtime.
* Реализовал реактивную state-driven модель подключения на базе экосистемы rx.
* Оптимизировал потребление ресурсов мобильного устройства:
  * адаптивная частота считывания параметров в зависимости от скорости движения и уровня заряда батареи,
  * минимизация сетевого трафика через batching, delta encoding и pbf,
  * использование mqtt (QoS 1)
* Организовал observability и диагностику мобильного клиента:
  * breadcrumbs,
  * логирование жизненного цикла подключения,
  * трассировка телеметрии,
  * сбор ошибок BLE/sync/parsing,
  * измерение влияние на батарею и performance background-режима.
* Реализовал visual regression/testing инфраструктуру для UI на основе собственной Storybook-like среды и Flutter
  Driver, что позволило изолированно тестировать экраны, сценарии отображения телеметрии и предотвращать визуальные
  регрессии без зависимости от backend и BLE-устройств.
* Реализовал unit-тестирование критичных модулей:
  * OBD packet parsing,
  * sync queue,
  * reconnect logic,
  * граничные сценарии обработки параметров.
* Разработал собственный эмулятор OBD для эффективной локальной отладки, reverse engineering готовых решений и эмуляции
  трудно-воспроизводимых сценариев.
* Реализовал нативную часть подключения и сопряжения с OBD, чтения геопространствнных данных на Kotlin используя реактивную
  парадигму (Kotlin Coroutines)

### Ключевые результаты и метрики:

* Снизил нагрузку на UI-поток за счёт вынесения обработки данных в isolates и event-driven rendering модели.
* Реализовал offline-first синхронизацию с сохранением телеметрии при нестабильной сети и автоматическим восстановлением

проектах компании для ускорения разработки, снижения количества регрессий и повышения стабильности релизов.

* Реализовал систему сравнения визуальных и поведенческих эталонов (screenshots + execution journal)
* Спроектировал режим UI для interactive replay, отладки и разработки функциональных сценариев
